## 🚀 快速开始

### 1. 定义 Schema

创建 XML schema 文件（`car.xml`）：

```xml
<?xml version="1.0" encoding="UTF-8"?>
<sbe:messageSchema xmlns:sbe="http://fixprotocol.io/2016/sbe"
                   package="example"
                   id="1"
                   version="1"
                   byteOrder="littleEndian">
    <types>
        <composite name="messageHeader">
            <type name="blockLength" primitiveType="uint16"/>
            <type name="templateId" primitiveType="uint16"/>
            <type name="schemaId" primitiveType="uint16"/>
            <type name="version" primitiveType="uint16"/>
        </composite>

        <enum name="Model" encodingType="uint8">
            <validValue name="A">0</validValue>
            <validValue name="B">1</validValue>
            <validValue name="C">2</validValue>
        </enum>

        <composite name="varStringEncoding">
            <type name="length" primitiveType="uint32"/>
            <type name="varData" primitiveType="uint8" length="0" characterEncoding="UTF-8"/>
        </composite>
    </types>

    <sbe:message name="Car" id="1">
        <field name="serialNumber" id="1" type="uint32"/>
        <field name="modelYear" id="2" type="uint16"/>
        <field name="code" id="3" type="Model"/>
        <data name="manufacturer" id="4" type="varStringEncoding"/>
        <data name="model" id="5" type="varStringEncoding"/>
    </sbe:message>
</sbe:messageSchema>
```

### 2. 生成 JavaScript 代码

```bash
# 方式 1：使用 Gradle
./gradlew generateNodeJsCodecs \
  -Dsbe.output.dir=nodejs/generated \
  -Dsbe.target.language=uk.co.real_logic.sbe.generation.nodejs.NodeJs

# 方式 2：使用 Java 命令行
java -Dsbe.output.dir=nodejs/generated \
     -Dsbe.target.language=uk.co.real_logic.sbe.generation.nodejs.NodeJs \
     -jar sbe-all/build/libs/sbe-all-*.jar \
     car.xml
```

生成的文件结构：
```
nodejs/generated/
├── Car.js              # 主消息类
├── Model.js            # 枚举
├── MessageHeader.js    # 消息头
└── ...
```

### 3. 使用生成的代码

```javascript
import { Car } from './generated/Car.js';
import { Model } from './generated/Model.js';

// === 编码 ===
const car = new Car();
car.serialNumber = 12345;
car.modelYear = 2024;
car.code = Model.A;
car.manufacturer = 'Toyota';
car.model = 'Camry';

const buffer = Buffer.allocUnsafe(512);
const size = car.encode(buffer, 0);
console.log(`✓ 编码了 ${size} 字节`);

// === 解码 ===
const car2 = new Car();
car2.decode(buffer, 0);
console.log(`制造商: ${car2.manufacturer}`);
console.log(`型号: ${car2.model}`);
console.log(`序列号: ${car2.serialNumber}`);
```

## 📦 安装与代码生成

### 环境要求

- **Node.js**: >= 14.0.0（需要 ES6 模块和 BigInt 支持）
- **Java**: >= 17（运行 SBE 代码生成器）
- **SBE**: 克隆或下载 SBE 项目

### 步骤 1：获取 SBE 工具

#### 方式 A：从源码编译（推荐）

```bash
# 1. 克隆 SBE 仓库
git clone https://github.com/real-logic/simple-binary-encoding.git
cd simple-binary-encoding

# 2. 编译项目（生成 sbe-all jar）
./gradlew build

# 3. 验证编译结果
ls -lh sbe-all/build/libs/sbe-all-*.jar
# 输出示例: sbe-all/build/libs/sbe-all-1.36.2.jar
```

#### 方式 B：下载预编译版本

```bash
# 从 GitHub Releases 下载
wget https://github.com/real-logic/simple-binary-encoding/releases/download/1.36.2/sbe-all-1.36.2.jar

# 或使用 Maven
# 添加到 pom.xml:
<dependency>
    <groupId>uk.co.real-logic</groupId>
    <artifactId>sbe-all</artifactId>
    <version>1.36.2</version>
</dependency>
```

### 步骤 2：准备 Schema 文件

创建你的 XML schema 文件（例如 `my-schema.xml`）：

```xml
<?xml version="1.0" encoding="UTF-8"?>
<sbe:messageSchema xmlns:sbe="http://fixprotocol.io/2016/sbe"
                   package="com.example"
                   id="1"
                   version="1"
                   byteOrder="littleEndian">
    <types>
        <!-- 必须包含 messageHeader -->
        <composite name="messageHeader">
            <type name="blockLength" primitiveType="uint16"/>
            <type name="templateId" primitiveType="uint16"/>
            <type name="schemaId" primitiveType="uint16"/>
            <type name="version" primitiveType="uint16"/>
        </composite>

        <!-- 可选：定义 varData 编码 -->
        <composite name="varStringEncoding">
            <type name="length" primitiveType="uint32"/>
            <type name="varData" primitiveType="uint8" length="0" characterEncoding="UTF-8"/>
        </composite>
    </types>

    <!-- 定义你的消息 -->
    <sbe:message name="MyMessage" id="1">
        <field name="field1" id="1" type="uint32"/>
        <!-- 更多字段... -->
    </sbe:message>
</sbe:messageSchema>
```

### 步骤 3：生成 JavaScript 代码

#### 方式 A：使用 Gradle（在 SBE 项目中）

```bash
# 在 SBE 项目根目录
./gradlew generateNodeJsCodecs \
  -Dsbe.output.dir=/path/to/your/project/generated \
  -Dsbe.target.language=uk.co.real_logic.sbe.generation.nodejs.NodeJs

# 示例：生成到当前目录的 generated 文件夹
./gradlew generateNodeJsCodecs \
  -Dsbe.output.dir=./generated \
  -Dsbe.target.language=uk.co.real_logic.sbe.generation.nodejs.NodeJs
```

#### 方式 B：使用 Java 命令行（推荐，更灵活）

```bash
# 基本用法
java -Dsbe.output.dir=./generated \
     -Dsbe.target.language=uk.co.real_logic.sbe.generation.nodejs.NodeJs \
     -jar sbe-all/build/libs/sbe-all-1.36.2.jar \
     my-schema.xml

# 指定命名空间
java -Dsbe.output.dir=./generated \
     -Dsbe.target.language=uk.co.real_logic.sbe.generation.nodejs.NodeJs \
     -Dsbe.target.namespace=com.mycompany.messages \
     -jar sbe-all-1.36.2.jar \
     my-schema.xml

# 多个 schema 文件
java -Dsbe.output.dir=./generated \
     -Dsbe.target.language=uk.co.real_logic.sbe.generation.nodejs.NodeJs \
     -jar sbe-all-1.36.2.jar \
     schema1.xml schema2.xml schema3.xml

# 使用 XSD 验证
java -Dsbe.output.dir=./generated \
     -Dsbe.target.language=uk.co.real_logic.sbe.generation.nodejs.NodeJs \
     -Dsbe.validation.xsd=sbe-tool/src/main/resources/fpl/sbe.xsd \
     -jar sbe-all-1.36.2.jar \
     my-schema.xml
```

#### 方式 C：创建生成脚本（推荐用于项目）

创建 `generate-codecs.sh`:

```bash
#!/bin/bash

# 配置
SBE_JAR="path/to/sbe-all-1.36.2.jar"
OUTPUT_DIR="./generated"
SCHEMA_FILE="./schemas/my-schema.xml"

# 清理旧代码
rm -rf "$OUTPUT_DIR"
mkdir -p "$OUTPUT_DIR"

# 生成代码
java -Dsbe.output.dir="$OUTPUT_DIR" \
     -Dsbe.target.language=uk.co.real_logic.sbe.generation.nodejs.NodeJs \
     -jar "$SBE_JAR" \
     "$SCHEMA_FILE"

# 检查结果
if [ $? -eq 0 ]; then
    echo "✓ 代码生成成功！"
    ls -lh "$OUTPUT_DIR"
else
    echo "✗ 代码生成失败！"
    exit 1
fi
```

使用：
```bash
chmod +x generate-codecs.sh
./generate-codecs.sh
```

#### 方式 D：使用 npm scripts

在 `package.json` 中添加：

```json
{
  "scripts": {
    "generate-sbe": "java -Dsbe.output.dir=./generated -Dsbe.target.language=uk.co.real_logic.sbe.generation.nodejs.NodeJs -jar ../sbe-all-1.36.2.jar ./schemas/my-schema.xml",
    "clean-sbe": "rm -rf ./generated && mkdir -p ./generated",
    "rebuild-sbe": "npm run clean-sbe && npm run generate-sbe"
  }
}
```

使用：
```bash
npm run generate-sbe
# 或重新生成
npm run rebuild-sbe
```

### 步骤 4：验证生成结果

```bash
# 检查生成的文件
ls -la generated/

# 应该看到类似输出：
# MessageHeader.js
# MyMessage.js
# (以及其他定义的类型)

cat generated/MyMessage.js
```

### 系统属性详解

| 属性 | 说明 | 示例 | 必填 |
|------|------|------|------|
| `sbe.output.dir` | 生成代码输出目录 | `./generated` | 是 |
| `sbe.target.language` | 目标语言<br/>**必须**: `uk.co.real_logic.sbe.generation.nodejs.NodeJs` | - | 是 |
| `sbe.target.namespace` | 覆盖 schema 中的 package | `com.example` | 否 |
| `sbe.validation.xsd` | XSD 验证文件路径 | `sbe.xsd` | 否 |
| `sbe.keyword.append.token` | JavaScript 关键字冲突时的后缀 | `_` | 否 |

### 常见生成问题

#### 问题 1：找不到 sbe-all jar

```bash
# 错误
Error: Unable to access jarfile sbe-all-*.jar

# 解决：使用完整路径
java -jar /full/path/to/sbe-all-1.36.2.jar ...
```

#### 问题 2：Java 版本不匹配

```bash
# 错误
Unsupported class file major version

# 检查 Java 版本
java -version  # 需要 >= 17

# 解决：安装 Java 17+
# macOS
brew install openjdk@17

# Ubuntu
sudo apt install openjdk-17-jdk

# 设置 JAVA_HOME
export JAVA_HOME=/path/to/java17
```

#### 问题 3：Schema 验证失败

```bash
# 错误
[Error] my-schema.xml:10:20: cvc-elt.1.a: Cannot find the declaration

# 原因：XML 格式错误
# 解决：检查 schema 格式，确保：
# 1. 有正确的 xmlns:sbe 命名空间
# 2. 有 messageHeader 定义
# 3. 所有引用的类型都已定义
```

#### 问题 4：输出目录权限问题

```bash
# 错误
Unable to create directory

# 解决：检查权限
mkdir -p ./generated
chmod 755 ./generated
```

## 📖 基本使用

### 消息编码

```javascript
import { Car } from './generated/Car.js';

// 1. 创建消息实例
const car = new Car();

// 2. 设置字段值
car.serialNumber = 12345;
car.modelYear = 2024;
car.manufacturer = 'Honda';
car.model = 'Civic';

// 3. 分配缓冲区（建议使用 allocUnsafe 以提高性能）
const buffer = Buffer.allocUnsafe(1024);

// 4. 编码到缓冲区
const bytesWritten = car.encode(buffer, 0);

// 5. 获取实际编码的数据
const encodedData = buffer.subarray(0, bytesWritten);

// 6. 发送或保存
sendToNetwork(encodedData);
// 或 fs.writeFile('car.bin', encodedData);
```

### 消息解码

```javascript
import { Car } from './generated/Car.js';

// 1. 接收数据
const buffer = await receiveFromNetwork();

// 2. 创建消息实例
const car = new Car();

// 3. 从缓冲区解码
const bytesRead = car.decode(buffer, 0);

// 4. 访问字段
console.log('序列号:', car.serialNumber);
console.log('年份:', car.modelYear);
console.log('制造商:', car.manufacturer);
console.log('型号:', car.model);
```

### 消息头处理

```javascript
import { MessageHeader } from './generated/MessageHeader.js';
import { Car } from './generated/Car.js';

// 编码时会自动包含 header
const car = new Car();
car.serialNumber = 12345;
const buffer = Buffer.allocUnsafe(512);
car.encode(buffer, 0); // 自动写入 header

// 解码时可以先读取 header 判断消息类型
const header = new MessageHeader();
header.decode(buffer, 0);

console.log('模板 ID:', header.templateId);
console.log('Schema ID:', header.schemaId);
console.log('版本:', header.version);

// 根据 templateId 选择正确的解码器
if (header.templateId === Car.TEMPLATE_ID) {
    const car = new Car();
    car.decode(buffer, 0);
}
```

## 🎯 数据类型详解

### 1. 基本数值类型

```javascript
// Schema 定义
<field name="price" id="1" type="int32"/>
<field name="quantity" id="2" type="uint16"/>
<field name="rate" id="3" type="float"/>

// JavaScript 使用
message.price = -12345;           // int32 → number
message.quantity = 100;           // uint16 → number
message.rate = 3.14159;           // float → number
```

**类型映射表**:

| SBE 类型 | JavaScript 类型 | 范围 |
|---------|----------------|------|
| `int8` | `number` | -128 到 127 |
| `uint8` | `number` | 0 到 255 |
| `int16` | `number` | -32768 到 32767 |
| `uint16` | `number` | 0 到 65535 |
| `int32` | `number` | -2^31 到 2^31-1 |
| `uint32` | `number` | 0 到 2^32-1 |
| `float` | `number` | IEEE 754 单精度 |
| `double` | `number` | IEEE 754 双精度 |

### 2. 64位整数（BigInt）

```javascript
// Schema 定义
<field name="timestamp" id="1" type="int64"/>
<field name="largeValue" id="2" type="uint64"/>

// JavaScript 使用（必须使用 BigInt）
message.timestamp = 1234567890123456789n;     // 注意 'n' 后缀
message.largeValue = 9223372036854775807n;

// 运算
const sum = message.timestamp + 1000n;
const product = message.largeValue * 2n;

// 与 number 转换
const asNumber = Number(message.timestamp);   // 可能丢失精度
const fromNumber = BigInt(123456);
```

> ⚠️ **重要**: 64位整数必须使用 `BigInt` 类型并加 `n` 后缀，否则会出现精度丢失！

### 3. 枚举类型

```javascript
// Schema 定义
<enum name="Color" encodingType="uint8">
    <validValue name="RED">0</validValue>
    <validValue name="GREEN">1</validValue>
    <validValue name="BLUE">2</validValue>
</enum>

<field name="color" id="1" type="Color"/>

// 生成的代码
const Color = {
    RED: 0,
    GREEN: 1,
    BLUE: 2
};

// JavaScript 使用
import { Color } from './generated/Color.js';

car.color = Color.RED;

// 或直接使用数值
car.color = 0;

// 判断
if (car.color === Color.GREEN) {
    console.log('汽车是绿色的');
}

// 反向查找（可选）
const colorNames = Object.keys(Color);
const colorName = colorNames.find(key => Color[key] === car.color);
console.log('颜色名称:', colorName); // 'RED'
```

**64位枚举**:

```javascript
// Schema
<enum name="LargeEnum" encodingType="uint64">
    <validValue name="HUGE">9223372036854775807</validValue>
</enum>

// 生成的代码（自动使用 BigInt）
const LargeEnum = {
    HUGE: 9223372036854775807n  // 注意 'n' 后缀
};

// 使用
message.largeValue = LargeEnum.HUGE;
```

### 4. 位集（BitSet）

```javascript
// Schema 定义
<set name="Options" encodingType="uint8">
    <choice name="sunRoof">0</choice>         <!-- 位 0 -->
    <choice name="sportsPack">1</choice>      <!-- 位 1 -->
    <choice name="cruiseControl">2</choice>   <!-- 位 2 -->
</set>

<field name="options" id="1" type="Options"/>

// 生成的类
class Options {
    constructor(value = 0) {
        this.value = value;  // 底层数值
    }

    get sunRoof() { return (this.value & 1) !== 0; }
    set sunRoof(val) {
        if (val) this.value |= 1;
        else this.value &= ~1;
    }

    get sportsPack() { return (this.value & 2) !== 0; }
    set sportsPack(val) {
        if (val) this.value |= 2;
        else this.value &= ~2;
    }

    get cruiseControl() { return (this.value & 4) !== 0; }
    set cruiseControl(val) {
        if (val) this.value |= 4;
        else this.value &= ~4;
    }
}

// JavaScript 使用
import { Options } from './generated/Options.js';

// 方式 1: 逐个设置
const options = new Options();
options.sunRoof = true;
options.sportsPack = false;
options.cruiseControl = true;
car.options = options;

// 方式 2: 直接赋值
car.options.sunRoof = true;
car.options.cruiseControl = true;

// 方式 3: 从数值构造
const options2 = new Options(7);  // 二进制: 111 (所有位为 1)
console.log(options2.sunRoof);      // true
console.log(options2.sportsPack);   // true
console.log(options2.cruiseControl); // true

// 获取底层值
console.log(car.options.value); // 5 (二进制: 101)
```

**64位位集**:

```javascript
// Schema
<set name="LargeFlags" encodingType="uint64">
    <choice name="flag40">40</choice>  <!-- 位 40 -->
</set>

// 生成的类（自动使用 BigInt）
class LargeFlags {
    constructor(value = 0n) {  // BigInt 默认值
        this.value = value;
    }

    get flag40() { return (this.value & (1n << 40n)) !== 0n; }
    set flag40(val) {
        if (val) this.value |= (1n << 40n);
        else this.value &= ~(1n << 40n);
    }
}

// 使用
const flags = new LargeFlags(0n);
flags.flag40 = true;
console.log(flags.value); // 1099511627776n (= 2^40)
```

### 5. 定长数组

#### 数值数组

```javascript
// Schema 定义
<type name="Prices" primitiveType="int32" length="5"/>
<field name="prices" id="1" type="Prices"/>

// JavaScript 使用
car.prices = [100, 200, 300, 400, 500];

// 访问元素
console.log(car.prices[0]);  // 100
console.log(car.prices.length); // 5

// 修改元素
car.prices[2] = 350;

// 循环
car.prices.forEach((price, index) => {
    console.log(`价格 ${index}: ${price}`);
});
```

#### 字符数组

```javascript
// Schema 定义
<type name="VehicleCode" primitiveType="char" length="6"/>
<field name="vehicleCode" id="1" type="VehicleCode"/>

// JavaScript 使用（作为字符串）
car.vehicleCode = 'ABC123';  // 6 个字符
console.log(car.vehicleCode); // 'ABC123'

// 较短的字符串（自动填充）
car.vehicleCode = 'XYZ';     // 实际存储: 'XYZ\0\0\0'
console.log(car.vehicleCode); // 'XYZ' (解码时移除 null)

// 注意：超长会被截断
car.vehicleCode = 'ABCDEFGHIJ'; // 只保留前 6 个: 'ABCDEF'
```

### 6. 复合类型

```javascript
// Schema 定义
<composite name="Engine">
    <type name="capacity" primitiveType="uint16"/>
    <type name="numCylinders" primitiveType="uint8"/>
    <type name="manufacturerCode" primitiveType="char" length="3"/>
</composite>

<field name="engine" id="1" type="Engine"/>

// 生成的类
class Engine {
    static SIZE = 6;  // 编码大小

    constructor() {
```

## ⚡ 性能优化

### 1. 缓冲区重用

```javascript
// ❌ 低效：每次都分配新缓冲区
function encodeCar(car) {
    const buffer = Buffer.allocUnsafe(1024);
    return car.encode(buffer, 0);
}

// ✅ 高效：重用缓冲区
class CarEncoder {
    constructor(maxSize = 4096) {
        this.buffer = Buffer.allocUnsafe(maxSize);
    }

    encode(car) {
        const size = car.encode(this.buffer, 0);
        return this.buffer.subarray(0, size);
    }
}

// 使用
const encoder = new CarEncoder();
const result1 = encoder.encode(car1);
const result2 = encoder.encode(car2);
```

### 2. 批量处理

```javascript
function encodeBatch(cars) {
    const buffer = Buffer.allocUnsafe(65536);  // 64KB
    const results = [];
    let offset = 0;

    for (const car of cars) {
        const size = car.encode(buffer, offset);
        results.push({
            data: buffer.subarray(offset, offset + size),
            size: size
        });
        offset += size;

        // 检查空间
        if (offset > 60000) {  // 留有余量
            console.warn('缓冲区快满了');
            break;
        }
    }

    return results;
}
```

### 5. BigInt 性能考虑

**重要**: JavaScript 的 `BigInt` 类型（用于 int64/uint64）比 `Number`（int32/uint32）慢 **2-5 倍**。

#### 性能影响测试结果

运行 `npm run benchmark` 查看详细结果：

| 操作类型 | int32 (Number) | int64 (BigInt) | 倍数 |
|---------|---------------|---------------|------|
| 算术运算 | 6ms | 29ms | **4.8x** |
| 位运算 | 1ms | 47ms | **47x** |
| Buffer 读写 | 13ms | 71ms | **5.5x** |
| 消息编解码 | 5ms | 25ms | **5.0x** |

#### 何时必须使用 int64/uint64

✅ **必须使用**（正确性要求）：

1. **时间戳** - 微秒/纳秒级时间戳
   ```xml
   <field name="timestamp" id="1" type="uint64"/>  <!-- 微秒时间戳 -->
   ```

2. **大 ID** - 订单 ID、交易 ID > 2^53
   ```xml
   <field name="orderId" id="1" type="uint64"/>  <!-- 9223372036854775807 -->
   ```

3. **金融数值** - 原子单位的价格（如分）
   ```xml
   <field name="priceInCents" id="1" type="int64"/>  <!-- 12345678901234 分 -->
   ```

4. **64 位位集** - 需要 > 32 个标志位
   ```xml
   <type name="Flags64" primitiveType="uint64">  <!-- 64 个布尔标志 -->
   ```

#### 何时应避免（使用 int32/uint32 代替）

⚠️ **可以避免**：

1. **计数器** - 大多数计数器 < 40 亿
   ```xml
   <field name="count" id="1" type="uint32"/>  <!-- 0 到 4,294,967,295 -->
   ```

2. **序列号** - 小 ID、数组索引
   ```xml
   <field name="sequenceNumber" id="1" type="uint32"/>
   ```

3. **数量** - 大多数数量 < 20 亿
   ```xml
   <field name="quantity" id="1" type="int32"/>  <!-- -2^31 到 2^31-1 -->
   ```

4. **小位集** - ≤ 32 个标志位
   ```xml
   <type name="Flags" primitiveType="uint32">  <!-- 32 个布尔标志 -->
   ```

#### Schema 设计示例

**❌ 不优化（全部使用 int64）**:
```xml
<message name="Order" id="1">
    <field name="orderId" id="1" type="int64"/>
    <field name="timestamp" id="2" type="int64"/>
    <field name="quantity" id="3" type="int64"/>      <!-- 浪费！ -->
    <field name="sequenceNum" id="4" type="int64"/>   <!-- 浪费！ -->
</message>
```
**性能**: 5 倍慢，消息体积大 60%

**✅ 优化后（按需使用 int64）**:
```xml
<message name="Order" id="1">
    <field name="orderId" id="1" type="int64"/>       <!-- 必须 64 位 -->
    <field name="timestamp" id="2" type="int64"/>     <!-- 必须 64 位 -->
    <field name="quantity" id="3" type="int32"/>      <!-- 20 亿足够 -->
    <field name="sequenceNum" id="4" type="uint32"/>  <!-- 40 亿足够 -->
</message>
```
**性能**: 更快，消息更小

#### 实际影响

- **10% int64 字段**: 约慢 10-20%（可接受）
- **50% int64 字段**: 约慢 50-100%（考虑优化）
- **100% int32 字段**: 无影响（最优）

#### 为什么需要 BigInt？

JavaScript 的 `Number` 使用 IEEE 754（53 位精度）：
- **安全范围**: -(2^53 - 1) 到 (2^53 - 1)
- **超出范围会丢失精度**

```javascript
// 没有 BigInt - 错误！
const large = 9007199254740993; // 2^53 + 1
console.log(large === large + 1); // true (!!)  <- 数据损坏

// 使用 BigInt - 正确
const largeBig = 9007199254740993n;
console.log(largeBig === largeBig + 1n); // false ✓
```

#### 优化建议

1. ✅ 在 schema 中使用合适的类型（默认 int32，必要时才 int64）
2. ✅ 运行基准测试：`npm run benchmark`
3. ✅ 查看详细文档：[PERFORMANCE.md](./PERFORMANCE.md)
4. ✅ **正确性 > 性能**：对于金融/时间戳数据，必须使用 int64

## ❓ 常见问题

### Q1: 为什么需要 BigInt？

**A**: JavaScript 的 `number` 类型使用 IEEE 754 双精度浮点数，只能安全表示 -(2^53-1) 到 (2^53-1) 之间的整数。超出此范围的64位整数会丢失精度。

```javascript
// 问题演示
const largeNumber = 9007199254740993;  // 2^53 + 1
console.log(largeNumber === largeNumber + 1);  // true！精度丢失

// 解决方案：使用 BigInt
const bigNumber = 9007199254740993n;
console.log(bigNumber === bigNumber + 1n);  // false，正确
```

### Q2: 如何判断是否需要使用 BigInt？

**A**:
- 如果字段类型是 `int64` 或 `uint64`，必须使用 BigInt
- 枚举和位集的底层编码类型是 `int64`/`uint64` 时，自动使用 BigInt
- 生成的 JSDoc 注释会标明类型：`{bigint}` 或 `{number}`

### Q3: 可以在浏览器中使用吗？

**A**: 不能直接使用。生成的代码依赖 Node.js 的 `Buffer` API。如需浏览器支持：
1. 使用 `buffer` polyfill: `npm install buffer`
2. 或修改生成器以使用 `ArrayBuffer`/`DataView`

### Q4: 字符编码如何选择？

**A**:
- **UTF-8**: 推荐，支持所有 Unicode 字符（中文、emoji 等）
- **ISO-8859-1** (Latin1): 单字节欧洲字符，性能更好
- **ASCII**: 仅 7位 ASCII 字符

```javascript
// UTF-8: 中文 3 字节/字符
const utf8Len = Buffer.byteLength('你好', 'utf8');  // 6

// Latin1: 单字节
const latin1Len = Buffer.byteLength('Hello', 'latin1');  // 5
```

### Q5: 如何处理版本兼容性？

**A**:
1. **Schema 版本**: 在 XML 中定义版本号
2. **检查版本**: 解码时检查 `header.version`
3. **向后兼容**: 新字段添加到末尾，设置默认值
4. **版本路由**: 根据版本使用不同的解码器

```javascript
const header = new MessageHeader();
header.decode(buffer, 0);

if (header.version === 1) {
    // 使用 v1 解码器
} else if (header.version === 2) {
    // 使用 v2 解码器
} else {
    throw new Error(`不支持的版本: ${header.version}`);
}
```

### Q6: 性能如何？

**A**: SBE 专为低延迟设计：
- **编码**: 通常 100-300 微秒
- **解码**: 通常 50-150 微秒
- **零拷贝**: 直接操作 Buffer，无中间对象
- **内存效率**: 紧凑的二进制格式

性能建议：
- 重用缓冲区
- 避免频繁 encode/decode
- 使用 `Buffer.allocUnsafe()` (小心，数据未初始化)

### Q8: 空值如何处理？

**A**: SBE 使用 `presence` 属性处理可选字段：

```xml
<field name="optionalField" id="1" type="uint32" presence="optional"/>
```

生成的代码会包含 null 值和特殊标记处理。

### Q9: 错误处理最佳实践？

**A**:

```javascript
function safeEncode(message) {
    try {
        const buffer = Buffer.allocUnsafe(4096);
        const size = message.encode(buffer, 0);
        return { success: true, data: buffer.subarray(0, size) };
    } catch (error) {
        console.error('编码失败:', error);
        return { success: false, error };
    }
}

function safeDecode(MessageClass, buffer) {
    try {
        const message = new MessageClass();
        const size = message.decode(buffer, 0);
        return { success: true, message, size };
    } catch (error) {
        console.error('解码失败:', error);
        return { success: false, error };
    }
}
```

```javascript
// 测试数据
const car = {
```
